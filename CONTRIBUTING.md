# Contributing to O3

Bug reports, fixes and ideas are welcome. A few ground rules first.

## Using AI is fine, hiding it isn't

You can use AI tools (ChatGPT, Claude, Copilot, whatever) to help you write code
or figure out a bug. Just say so. Every issue and pull request has to state
whether AI was used and for what. For example:

- "No AI used."
- "Used Copilot for autocomplete in `probes.c`."
- "Asked ChatGPT to explain the Task Scheduler API, wrote the code myself."
- "The fix in `system_items.inc` was mostly generated by Claude. I tested it on
  Windows 11 23H2."

If it turns out AI was used and not mentioned, the issue or PR gets closed.

## Write issues in your own words

Don't paste an AI-written bug report. Tell us what you did, what you expected
and what happened instead, the way you'd explain it to a friend. Bad English or
bad Indonesian is completely fine. A short honest report beats a long polished one.

Things that help:

- Windows version (Settings > System > About)
- O3 version
- Which tab and which item
- The result code you got (`200` or `55012`)
- A screenshot if you can

## Pull requests

- Keep one PR to one change.
- Say what you tested and on what Windows version.
- O3 touches services and scheduled tasks, so don't add anything to the CPU/RAM
  lists that can stop Windows from booting, signing in or staying secure.
- Keep it light. No new runtime dependencies, no C runtime, no frameworks.
- The code must still build with `build.cmd` (NASM + MinGW-w64).

## Selling

By sending a PR you agree it is released under this repo's [LICENSE](LICENSE).
Once your PR is merged, you're allowed to sell O3 as described there. A PR that
isn't merged doesn't give you that right.
